Projects

What has been built at DreamSpace Academy, one page each.

This is what has been built: machines, tools, prototypes and software, one page each. A project keeps its own page independently of the day it was made, because the useful question about a thing that exists is not when it happened but what problem it took on, what was tried, and where it got to.

It is written for someone about to start their own build. The failures and the half-finished ones are here too, and they are usually the more useful pages.

What the label on each project means

Every project says what DreamSpace Academy actually did, because five quite different things get flattened by the word "built": the organisation originating work, a learner building something with support, the lab making a tool for itself, an outside team being hosted, and cases where who made what is still being established. All five are on this page and each says which it is.

Nothing here yet

The first project pages are being written. They are added one at a time, each from the record of what was actually built rather than from a list of titles, so this page fills slowly and every entry on it can be checked.

In the meantime the activity record holds the days on which much of this work happened.

How this list is kept

A project earns a page from the record of what was built, not from a list of names, and each one says what DreamSpace Academy did rather than implying the organisation made everything on the page. A project marked as a learner’s is the learner’s work, and one marked as hosted belongs to the team that did it.

Where a maker is named it is because they agreed to be. A project with no name attached is not an oversight; it is the ordinary case, and the work still belongs to whoever built it.
